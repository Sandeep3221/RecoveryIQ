# Synthetic Recovery Dataset v1

RecoveryIQ's Stage 5B model is trained and evaluated on synthetic recovery episodes because production merchant subscription-failure histories are unavailable. The dataset generator and assumptions are published. Model metrics and recovery probabilities are simulation results and must not be interpreted as real-world merchant performance.

`synthetic_recovery_v1.csv` contains 5,000 episodes generated by `generate_dataset.py` with NumPy random seed 42. One row represents one failed recurring-payment episode, one candidate action actually attempted in the simulation, and one sampled seven-day outcome. It does not duplicate a context into four counterfactual observations.

## Fields

| Field | Meaning |
|---|---|
| `episodeId` | Stable synthetic row identifier |
| `amountMinor` | Subscription amount in integer paise |
| `failureCategory` | Existing RecoveryIQ deterministic diagnosis category |
| `paymentMethod` | `card`, `upi`, `emandate`, `netbanking`, or `unknown` |
| `subscriptionStatus` | Primarily `pending` or `halted` |
| `failureCount` | Unique failures attached to the synthetic case |
| `consecutiveFailureCount` | Synthetic subscription consecutive-failure counter |
| `subscriptionAgeDays` | Age known at decision time |
| `previousRecoveryRate` | Prior recovered failures divided by prior failures |
| `previousFailedPayments` | Prior failed-payment count |
| `previousNudges` | Nudges known at decision time |
| `nativeRetryPossible` | Whether Razorpay status indicates native retry opportunity |
| `downtimeActive` | Confirmed relevant downtime at diagnosis time |
| `diagnosisConfidence` | `HIGH`, `MEDIUM`, or `LOW` |
| `candidateAction` | The one action observed in this synthetic episode |
| `downtimeSeverity` | `low`, `medium`, `high`, or `none` |
| `caseAgeHours` | Case age at the simulated decision point |
| `recoveredWithin7Days` | Binary synthetic outcome and model target |

No future payment state, recovered amount, eventual recovery time, next webhook, or other outcome-derived feature is included.

## Published assumptions

Failure-category probabilities are 25% temporary funds, 20% bank/network, 18% invalid payment method, 15% customer authentication, 10% invalid mandate/auth, and 12% unknown. Candidate-action probabilities are 30% wait, 27% nudge, 25% card update, and 18% stop/escalate. Payment-method probabilities are 52% card, 24% UPI, 11% e-mandate, 10% netbanking, and 3% unknown. These are simulation assumptions, not Razorpay statistics.

`synthetic_success_probability` uses a published logistic latent score with general context effects, action effects, failure-category effects, and limited action/context interactions. All coefficients are visible in `generate_dataset.py`. Probabilities are clamped to 0.02-0.95, then outcomes are sampled from a seeded Bernoulli distribution. The simulator is separate from `heuristic-v1` and does not import its configuration.

This dataset must not be interpreted as merchant production history, Razorpay transaction statistics, causal evidence, or measured revenue uplift.
